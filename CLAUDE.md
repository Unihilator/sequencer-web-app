# Проєкт: особисте портфоліо + онлайн-секвенсер

@AGENTS.md

## Про мене

- 15+ років досвіду в iOS (Swift, SwiftUI, UIKit, Core Audio — базово). Трохи фронтенду, SEO — нуль.
- Мета проєкту — НАВЧИТИСЯ і пройти всі ланки створення сайту: код, хостинг, домен, DNS, CI/CD, SEO, аналітика, запуск.
- Тому пояснюй ключові рішення коротко і по суті. Де доречно, проводь аналогії з iOS (наприклад, React state ↔ SwiftUI @State, useEffect ↔ onAppear/task).
- Спілкуйся зі мною українською. Код, коментарі в коді, назви комітів — англійською.

## Що будуємо

1. Головна — ефектний сайт-портфоліо в стилі openai.com/codex, apple.com: скрол-анімації, плавний скрол, 3D/шейдерний hero.
2. /sequencer — онлайн step-sequencer (12 треків: барабани, FX, bass, synth; 16/32 кроки; reverb/delay sends; придатний для DnB): гарний, аудіо-реактивні візуали, шеринг патернів через URL. Головний «експонат» портфоліо.
   - Спільна сесія: посилання-запрошення /sequencer/live/[id], кілька людей редагують один патерн і стартують синхронно (усі учасники рівні).
3. /projects — мої iOS-застосунки.
4. /blog — статті (MDX), основне джерело SEO-трафіку.
5. Пізніше: двомовність uk/en.

## Стек (використовуй останні стабільні версії; перевіряй актуальний API в документації, не вигадуй)

- Next.js (App Router) + TypeScript (strict) + pnpm
- Tailwind CSS
- Motion (ex Framer Motion) — UI-анімації
- GSAP + ScrollTrigger, Lenis — скрол-анімації і smooth scroll
- Three.js + React Three Fiber + drei, GLSL — 3D і шейдери
- Tone.js поверх Web Audio API — аудіо
- Zustand — стан
- MDX — блог
- Vitest — unit-тести, Playwright — e2e
- ESLint + Prettier
- Хостинг: Vercel. DNS/домен: Cloudflare (imsequencer.dev). CI: GitHub Actions.
- Спільна сесія (Етап 3): кімнати на Cloudflare Durable Objects (PartyServer) — Vercel не тримає WebSocket.

## Архітектурні принципи

- Аудіо-движок живе в src/audio і НЕ залежить від React (жодних імпортів React). UI спілкується з ним через Zustand-стор або тонкий API.
- Таймінг — ТІЛЬКИ через годинник AudioContext / Tone.Transport. Ніколи не використовуй setTimeout/setInterval для планування нот. Візуальну синхронізацію роби через Tone.Draw / requestAnimationFrame.
- AudioContext запускається лише після жесту користувача (вимога браузерів, особливо iOS Safari).
- Дії стора секвенсера — серіалізовувані команди (`{ type: "toggleStep", ... }`), а не довільні функції: ті самі команди потім ідуть мережею в спільній сесії.
- Мережею передаються лише команди і час старту, не аудіо: кожен клієнт синтезує звук локально. Движок уміє стартувати в заданий момент (`play(atTime?)`).
- Формат патерну в URL має байт версії; нові можливості (акценти тощо) — лише через нову версію, старі посилання мають і далі декодуватися.
- Контент сторінок рендериться на сервері (SSR/SSG) — це критично для SEO. Важкі 3D/аудіо-компоненти вантаж ліниво (dynamic import, ssr: false) з легким фолбеком.
- Поважай prefers-reduced-motion: вимикай або спрощуй важкі анімації.
- Бюджет продуктивності: LCP < 2.5s, INP < 200ms, CLS < 0.1; Lighthouse ≥ 90 у всіх категоріях.
- Кожна сторінка має metadata: title, description, canonical, Open Graph.
- Доступність: семантичний HTML, фокус із клавіатури, aria там, де потрібно (сітка секвенсера теж має керуватися з клавіатури).
- Структуру маршрутів проєктуй так, щоб пізніше легко додати /[locale] для uk/en.

## Структура (орієнтир, можна уточнювати)

- src/app — маршрути (/, /sequencer, /projects, /blog, /blog/[slug])
- src/audio — аудіо-движок (engine, instruments, pattern, encoding)
- src/components — UI-компоненти; src/components/three — 3D-сцени
- src/lib — утиліти, seo-хелпери, аналітика
- src/store — Zustand-стори
- content/blog — MDX-статті
- docs — документація і план

## Команди

- pnpm dev / pnpm build / pnpm lint / pnpm typecheck / pnpm test / pnpm test:e2e
- pnpm format (записати) / pnpm format:check (перевірити, як у CI)
- Один unit-тест: `pnpm test src/app/page.test.tsx` або `pnpm test -t "назва тесту"`; watch-режим: `pnpm test:watch`
- Один e2e-тест: `pnpm test:e2e e2e/home.spec.ts --project=chromium`
- Unit-тести лежать поруч із кодом (`src/**/*.test.ts(x)`), e2e — у `e2e/`. Playwright сам піднімає `pnpm dev` (у CI — `build && start`); проєкти: chromium і mobile-safari (WebKit, iPhone 15).

## Правила роботи

- Працюй малими кроками. Один логічний крок — один коміт у форматі Conventional Commits (feat:, fix:, chore:, docs:...).
- Перед великими змінами коротко опиши план і чекай мого підтвердження.
- Після кожного кроку повідом: що зроблено, як це перевірити, що я маю зробити руками.
- Не додавай нові залежності без короткого пояснення, навіщо вони.
- Ручні дії (купівля домену, створення акаунтів, налаштування DNS, верифікація в Search Console тощо) ти виконати не можеш — давай мені покрокову інструкцію і чекай підтвердження. Позначка в плані для таких пунктів: 👤.
- Не зберігай секрети в репозиторії. Використовуй .env.local і додай .env.example.
- Після виконання пунктів відмічай чекбокси в docs/PLAN.md.
- Якщо щось у плані виглядає застарілим чи неоптимальним, скажи про це і запропонуй альтернативу.
