## Архітектурні принципи
- Аудіо-движок живе в src/audio і НЕ залежить від React (жодних імпортів React). UI спілкується з ним через Zustand-стор або тонкий API.
- Таймінг — ТІЛЬКИ через годинник AudioContext / Tone.Transport. Ніколи не використовуй setTimeout/setInterval для планування нот. Візуальну синхронізацію роби через Tone.Draw / requestAnimationFrame.
- AudioContext запускається лише після жесту користувача (вимога браузерів, особливо iOS Safari).
- Контент сторінок рендериться на сервері (SSR/SSG) — це критично для SEO. Важкі 3D/аудіо-компоненти вантаж ліниво (dynamic import, ssr: false) з легким фолбеком.
- Поважай prefers-reduced-motion: вимикай або спрощуй важкі анімації.
- Бюджет продуктивності: LCP < 2.5s, INP < 200ms, CLS < 0.1; Lighthouse ≥ 90 у всіх категоріях.
- Кожна сторінка має metadata: title, description, canonical, Open Graph.
- Доступність: семантичний HTML, фокус із клавіатури, aria там, де потрібно (сітка секвенсера теж має керуватися з клавіатури).
- Структуру маршрутів проєктуй так, щоб пізніше легко додати /[locale] для uk/en.

## Правила роботи
- Працюй малими кроками. Один логічний крок — один коміт у форматі Conventional Commits (feat:, fix:, chore:, docs:...).
- Перед великими змінами коротко опиши план і чекай мого підтвердження.
- Після кожного кроку повідом: що зроблено, як це перевірити, що я маю зробити руками.
- Не додавай нові залежності без короткого пояснення, навіщо вони.
- Ручні дії (купівля домену, створення акаунтів, налаштування DNS, верифікація в Search Console тощо) ти виконати не можеш — давай мені покрокову інструкцію і чекай підтвердження. Позначка в плані для таких пунктів: 👤.
- Не зберігай секрети в репозиторії. Використовуй .env.local і додай .env.example.
- Після виконання пунктів відмічай чекбокси в docs/PLAN.md.
- Якщо щось у плані виглядає застарілим чи неоптимальним, скажи про це і запропонуй альтернативу.
